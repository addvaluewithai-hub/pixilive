# Character Engine architecture

## Ownership

React owns the interface and selected character. The SVG adapter owns the renderer lifecycle. The performance director owns expression and gesture arbitration. The playback clock owns audio scheduling and mouth samples. Gemini requests semantic performance cues; it never writes SVG coordinates.

The director samples against `AudioContext.currentTime` during Live playback and a monotonic clock during offline demonstrations. Animation geometry is updated locally per frame. A switch disposes the old rig and cancels its pending performance while the PCM stream and conversation continue.

## Timing boundary

Gemini cues have no authoritative alignment to their intended words in this implementation. Narrative cues (`next_audio`, also the default) wait for the next received audio chunk and use its scheduled playback start. Direct face/gesture requests use `immediate` on the current playback clock, even without speech. At turn completion, pending cues without a following chunk fall back to the current playback time instead of silently disappearing. Multiple cues due in one frame resolve to the latest; skipped cues are reported, not played as a burst. This is best-effort phrase timing, not word-level synchronization. A production-quality semantic alignment layer needs a measured protocol or alignment source and a latency budget.

Mouth samples are generated by the inherited acoustic analyzer and sampled on the playback clock. The transcript-letter timing guide is intentionally not fed into the Live path. The analyzer is a heuristic fallback; it is not an Arabic phoneme recognizer and cannot promise every consonant is classified correctly. The mouth renderer supports 12 visemes, including closure, teeth and tongue poses, independently of detection quality. REST/MBP closure uses faster settling than other channels.

`turnComplete` means generation finished. Listening only resumes after scheduled playback drains. Interruption clears both queued sound and visual cues. A client-side interrupt suppresses remaining output until server interruption or turn completion. Reconnection may resume an existing session; explicit close clears the handle.

## Reuse and isolation

- `public/character-engine`: our Character Lab master and shared geometry/rig, extended with direct mouth, intensity, cancellation and independent gesture APIs.
- `VisemeAnalyzer.ts`: acoustic fallback adapted from PixiLive main (`d85f0d5`). Its limitations are retained and documented rather than presented as precise lip sync.
- `audio-capture.worklet.js`: the reviewed capture processor from main.
- New application, director, playback clock, resampler lifecycle, and Gemini adapter do not depend on old Pixi/Rive character classes or iframe/button bridges.

2. Exercise Arabic speech, silence, fast phrases, laughter, and interruptions on desktop and mobile.
3. Measure perceived timing including output-device latency, stalls, suspended audio contexts and network jitter.
4. Review arms/tails while switching gestures and switching characters mid-speech.
5. Before exposing the token endpoint publicly, apply the application's authentication and rate limits at the server/edge. The endpoint currently checks request origin, constrains tokens, uses one-use short-lived credentials, and avoids returning upstream secrets; origin checks are not user authentication.

No production deployment or merge is part of this branch delivery.

## Verifiable performance requests

The setup prompt explains that Gemini performs the visible avatar, lists every supported expression and gesture, and requires `perform` for direct face/gesture requests. Long-story requests take precedence over ordinary concise conversation. The selected avatar is included at connection/setup time; switching mid-session changes the renderer without injecting a conversational turn. The prompt explicitly allows appearance changes and does not pretend the model can see the screen.

The Live test panel sends either a direct thinking request or a six-scene story request to Gemini. It does not trigger local choreography. Its bounded trace records actual server tool calls, validation, scheduling, cancellation, skipped cues and dispatch to the renderer. Silent demonstrations and manual controls do not increment these counters. An applied trace means renderer methods were called, not that animation quality or perceived synchronization has been visually verified. The panel shows the model identifier requested by the token endpoint.

Acceptance on a real session: ask for a thinking face and watch it change; then run the story test and check that six scene-appropriate cues arrive over the story and visibly match the narration. A spoken description with no tool call is a failed model-performance test. Mock protocol tests cannot establish model compliance, story length, or real-device audiovisual quality.

The Copy log button exports readable conversation messages and one updated entry per actual server tool call, with model, selected-avatar changes, cue parameters, status and exception reason. Transcript chunks are merged. Audio payloads, credentials, frame updates and transport chatter are excluded. Story-test instructions are summarized explicitly as a test request. Logs remain in memory, reset on a new session, retain up to 500 entries and disclose truncation. If clipboard access fails, selectable text is shown.
